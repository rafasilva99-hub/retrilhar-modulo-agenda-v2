Bloco 3 de N — Módulo: Vendedores e Afiliados

Fontes cruzadas: Módulo Central de Vendas (escopo com user stories dos perfis Vendedor e Afiliado), reunião 25/03 (discussão extensa sobre afiliados e vendedores com o Cristiano e a Katiely como referência), reunião 01/04, backlog atual do projeto. Contexto do módulo: Vendedores e Afiliados são módulos separados mas compartilham lógica (listagem, cadastro, performance, comissões). No Figma atual, ambos estão como itens independentes no menu, refletindo a estrutura do escopo que separa "Gestão de Vendedores" e "Gestão de Afiliados". Diferença fundamental (reunião 25/03, Cristiano): o afiliado é pessoa física que faz contrato com as empresas — "sempre tem o mesmo código, só que manda para lojas diferentes". Isso tem impacto em como o painel do afiliado precisa estruturar visualizações por contrato (quando a mesma pessoa é afiliada de múltiplas empresas).

Tarefa 6 — Painel do Afiliado (interface externa)

Título: [RETRILHAR] [AFILIADOS] Painel do Afiliado (interface externa) Status: DESIGN Tags: media · fluxo

Descrição

OBJETIVO Interface separada acessada apenas pelo afiliado (perfil externo). Layout simplificado sem menu completo do sistema. O afiliado só vê as suas vendas, suas comissões e seu link/código exclusivo. É um spin-off do painel principal. HISTÓRICO DE DECISÕES E MUDANÇAS

  • Reunião 25/03 (Rafael): "Menu é claramente mais enxuto aqui. No início temos as visualizações gerais. Tomei o cuidado de atribuir todas as informações aqui sem ele precisar prosseguir para outros fluxos. No cenário em que o usuário quer visualizar as informações rapidamente, ele já consegue ver tudo no overview, justamente na página inicial".
  • Reunião 25/03 (Rafael): "Header com saudação como padrão. Subtítulo com atualização dos dados — o intuito é fazer o afiliado perceber que está no painel próprio e atualizado. As indicações com quatro métricas principais: listagem das indicações feitas nos últimos 30 dias, vendas abandonadas da última semana, valor recebido no mês, valor que vai receber nos próximos 7 dias".
  • Reunião 25/03 (Cristiano): "o afiliado é pessoa física que gera contrato com nossos clientes. Ele indica, leva compradores para as lojas dos clientes. Mentaliza a Katiely — ela é afiliada de três clientes nossos, sei lá, Cerrado Experience, Ibertaco e Trilheiras de Brasília. Vai ter link para cada desses contratos que ela tem, para ela trabalhar. Então sempre vai ter esse recorte que é de qual é o contrato dela ali. A ideia é a gente pensar nisso — por exemplo, quanto eu estou gerando para cada contrato? Quanto cada contrato está me pagando de comissão?".
  • Reunião 25/03 (Cristiano): "ele tem código único, só que manda para lojas diferentes. É pessoa física — faz contrato da pessoa física com as empresas. É sempre o mesmo código. É o identificador dele, ele está prestando serviço para as empresas".
  • Reunião 25/03 (Cristiano): "Uma coisa que pode pensar é ter filtro se ele está olhando todos os contratos ou se pode escolher contrato específico — a gente soma os valores se for todos os contratos".
  • Reunião 25/03 (Rafael): passo a passo numerado de três passos explicando as comissões de forma resumida. "Serve como onboarding para afiliados novos e reforço de confiança para afiliados ativos há mais tempo. Escolhi esse formato ao invés de modal com question mark para que a informação fique sempre visível". OBSERVAÇÕES
  • Menu do painel do afiliado: Painel Inicial, Lista de Vendas, Extrato de Comissões, Configurações (escopo).
  • Link do afiliado precisa ter destaque visual com botão de copiar — ação primária do perfil.
  • Tentativa de acesso a rotas do painel admin deve redirecionar — perfil restrito.
  • Estrutura para múltiplos contratos (afiliado que atende várias empresas) ainda precisa de proposta de arquitetura — o Rafael sinalizou que vai estruturar com lista semelhante à de vendas, mas "ainda vou buscar algumas soluções de arquitetura para isso". BLOQUEIOS
  • Arquitetura para exibir múltiplos contratos do mesmo afiliado: Rafael sinalizou que ainda estava buscando soluções (reunião 25/03). Status atual dessa decisão — em aberto.
  • Filtro "todos os contratos vs. contrato específico" mencionado pelo Cristiano: precisa ser estruturado junto com a decisão acima.

Tarefa 7 — Painel do Vendedor (interface externa)

Título: [RETRILHAR] [VENDEDORES] Painel do Vendedor (interface externa) Status: BACKLOG Tags: media · fluxo

Descrição

OBJETIVO Interface dedicada ao vendedor quando loga no sistema (sem acumular cargo de gestor). Permite criar vendas manuais, acompanhar pedidos próprios, ver extrato de comissões e receber o link de vendas para enviar aos clientes. HISTÓRICO DE DECISÕES E MUDANÇAS

  • Escopo Central de Vendas define menu do painel: Painel de Vendas e Relatórios, Extrato de Comissões, Configurações.
  • Escopo (nota): "o vendedor poderá ver as vendas que ele originou seja manualmente (offline) ou pelo link dele de vendas. Ele só poderá ver as vendas de outros vendedores se tiver acumulado o cargo de gestor".
  • User stories do vendedor (escopo): painel próprio de vendas, consultar produtos que pode vender e comissões, criar vendas manuais com link para cliente pagar, definir tempo para bloquear vagas, conferir pedidos em aberto/pagos/não concluídos, enviar link de vendas, histórico completo de ações por usuário com data e horário para rastrear qualquer ação. OBSERVAÇÕES
  • Criar venda manual aqui reutiliza o fluxo de "Novo Pedido" do módulo Vendas — não é necessário duplicar.
  • Dar baixa em pedido (confirmar pagamento manual) é ação específica do vendedor, pós-venda.
  • Rastreabilidade por usuário é requisito forte do escopo — histórico com data/horário em todas as ações. BLOQUEIOS Nenhum.
