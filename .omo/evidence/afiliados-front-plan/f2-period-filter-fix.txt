## Hypotheses and distinguishing evidence

1. H1, user-code logic: period state is omitted from the displayed collection projection. Distinguishing evidence: source calls above contain no date predicate; a period-only DOM test finds a date-out-of-range row before and after changing the selector. Fix: add a page-local date projection before existing service filters.
2. H2, date-field choice: the correct referral date is `purchaseDate` and the correct commission date is `dataGeracao`, not activity/settlement dates. Distinguishing evidence: the fixture type declarations and rendered page labels use those exact fields. Fix: filter on the displayed transaction date fields.
3. H3, period-boundary stability: using the host clock would make static fixture rows change as time moves, while the fixture set has a stable latest transaction date. Distinguishing evidence: the latest referral purchase and commission generation dates are both `2026-07-06`; period windows can be anchored to that existing fixture date and remain deterministic. Fix: derive boundaries from the latest date in the relevant fixture collection.
