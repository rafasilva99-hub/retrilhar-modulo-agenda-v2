Componentes — Padrões e Regras

Hierarquia de componentes

components/ui/          ← shadcn/ui (Radix). NÃO editar, NÃO criar novos aqui
components/custom/      ← Componentes do projeto. Criar novos aqui
components/layout/      ← PageContainer, MobilePageContainer, MobileTopBar
components/pages/       ← Conteúdo extraído de páginas complexas
components/dashboard/   ← Widgets do dashboard

Antes de criar qualquer componente

  1. Verificar components/custom/index.ts — já existe?
  2. Verificar components/ui/index.ts — o shadcn já tem isso?
  3. Se existir, USAR o existente. Não recriar.

Criando novo componente custom

// components/custom/meu-componente.tsx
import { cn } from "@/lib/utils";
import { Icon } from "@/components/ui/icon";

// Exportar interface de props
export interface MeuComponenteProps {
  title: string;
  className?: string;
}

/**
 * Descrição breve do componente.
 */
export function MeuComponente({ title, className }: MeuComponenteProps) {
  return (
    <div className={cn("bg-white rounded-[var(--radius-card-md)] p-4", className)}>
      <Icon name="star" size={20} className="text-brand-500" />
      <span>{title}</span>
    </div>
  );
}

Depois de criar, adicionar no barrel export:

// components/custom/index.ts
export { MeuComponente } from "./meu-componente";
export type { MeuComponenteProps } from "./meu-componente";

Regras

  • Sempre exportar componente como named export (não default)
  • Sempre exportar interface de props
  • Sempre aceitar className?: string para composição
  • Usar cn() de @/lib/utils para merge de classes
  • Ícones:
  • Cores: classes Tailwind do design system (nunca hex hardcoded)
  • Border radius: usar CSS variables (var(--radius-card-md), var(--radius-pill))
  • Shadows: usar CSS variables (var(--shadow-card), var(--shadow-elevated))
  • Adicionar JSDoc com descrição breve

NÃO editar components/ui/

Os arquivos em components/ui/ são gerados pelo shadcn/ui CLI. Se precisar customizar visual, usar CSS variables em globals.css ou sobrescrever via className.
